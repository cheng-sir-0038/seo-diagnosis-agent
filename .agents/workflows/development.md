# 开发工作流

用于在本仓库实现需求、修复问题或调整界面。

1. 确认当前分支和工作区状态，阅读 [项目说明](../../README.md)、相关代码、调用方与测试。
2. 确定受影响的接口、数据和页面；修复问题时先复现并定位原因，再做最小改动。
3. 业务逻辑优先使用真实实现验证；模型和第三方 API 等外部依赖可以隔离。
4. 按改动范围运行相关测试。Agent Loop 可从 `tests/agent/` 开始，SEO Chat 与审批可从 `tests/seo_agent/` 开始，轨迹评测在 `tests/agent_evals/`；前端改动使用 `frontend/` 的测试或类型检查。
5. 检查 `git diff --check`，报告实际验证结果和未验证的真实服务边界。不要为了验证重复重建已有数据库或环境。

不要将真实 API Key、OAuth 凭据、SQLite 数据或内部资料加入仓库。提交、推送和发布遵循任务中明确的授权。
